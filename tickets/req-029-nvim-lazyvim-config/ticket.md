# Neovim config: adopt LazyVim with Catppuccin

## Why

`configs/nvim` is a hand-rolled minimal lazy.nvim setup: `init.lua` bootstraps
lazy.nvim and loads six per-plugin files under `lua/plugins/`. It is not the
LazyVim distribution, so it misses LazyVim's defaults, extras, keymaps,
health checks and plugin set.

The desired ownership split is:

- provisioning owns the Neovim **binary** and the static config copy;
- LazyVim/lazy.nvim own **plugin resolution and installation** on first launch.

No provisioning task may run `:Lazy sync`. The generated-palette integration is
a separate follow-up (`REQ-116` / `REQ-117` in `dotfiles-v3`); this ticket keeps
Catppuccin as the active colorscheme for now.

## Requirement

1. Replace `configs/nvim` with the LazyVim starter layout:

   ```text
   configs/nvim/
   ├── init.lua
   ├── lazy-lock.json
   └── lua/
       ├── config/
       │   ├── lazy.lua
       │   ├── options.lua
       │   ├── keymaps.lua
       │   └── autocmds.lua
       └── plugins/
           ├── lazyvim.lua
           └── lsp.lua
   ```

2. `init.lua` is `require("config.lazy")`; `lua/config/lazy.lua` is the upstream
   starter (bootstrap lazy.nvim, import `lazyvim.plugins`, then local `plugins`).
3. `lua/config/options.lua`, `keymaps.lua` and `autocmds.lua` stay empty: use
   LazyVim defaults (2-space expandtab, `<leader>e` explorer, `<leader>ff` /
   `<leader>sg` pickers, `<leader>qq` quit).
4. `lua/plugins/lazyvim.lua` selects Catppuccin temporarily:

   ```lua
   return {
     { "LazyVim/LazyVim", opts = { colorscheme = "catppuccin" } },
   }
   ```

5. `lua/plugins/lsp.lua` adds `bashls`; `lua_ls` is already a LazyVim default:

   ```lua
   return {
     { "neovim/nvim-lspconfig", opts = { servers = { bashls = {} } } },
   }
   ```

6. Delete the old `lua/options.lua` and `lua/plugins/{catppuccin,lsp-config,lualine,neo-tree,telescope,treesitter}.lua`.
7. Do **not** enable the Telescope extra; LazyVim defaults to the Snacks picker.
8. Commit `lazy-lock.json` as an explicit plugin-revision pin. It is the one
   deliberate exception to the "generated artifacts are never assets" rule;
   document that in `configs/README.md` and the `CHANGELOG.md` Unreleased entry.
9. Update `configs/README.md` and `catalog.yaml` `classes.configs.contents` to
   the new file count and the LazyVim description. Do **not** change
   `catalog.yaml` `tag`.

## Lockfile constraint

`lazy-lock.json` is generated by a first LazyVim launch. Generating it requires
running Neovim with network access; if that is treated as an install/apply under
the current forbidden-action policy, leave the lockfile step blocked and record
it as such. The rest of the config can land without it. Never run `:Lazy sync`
from provisioning and never install Neovim via provision under this ticket.
